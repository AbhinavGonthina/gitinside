# M9.6: full regression and accessibility audit

2026-11-11, branch `task/m9.6`. The audit is `apps/web/e2e/a11y.e2e.ts` (ADR-0263); it now runs on every push in CI's `web-e2e` job.

## What the audit checks

axe-core 4.14 (`@axe-core/playwright` 4.14.0) with the `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22a`, and `wcag22aa` rule tags, on the production build (`next build`), in Chromium at 1280×720, in dark and in light. 22 screens, 44 runs:

| Site | Screens |
|---|---|
| Unconfigured (no database) | landing; landing with the field's error; How it works; Limits; Privacy; Self-hosting; the 404 page; a job's progress page; a permalink while analysis is unavailable |
| Seeded (`fixtures/shop-demo`) | repo page: first-visit tips; diagram; a selection with its code; a trace at step 2; the trace picker; the legend; search with results; filters; Share; Add to README; compared with a commit |
| Signed in (fake GitHub) | the dashboard; a private repo's job progress page |

A run passes only with no violation, measured once no finite animation is running (an entrance fade read halfway is a blend of text and background, which the first runs showed as a false 3.93:1 and 1.07:1).

## What it found, and what changed

The first run (before any fix): 23 of 44 failed. Three of the causes were the tests' own (a trace button the website's header doesn't have; the Add to README preview asking GitHub for a fixture that isn't there, which then hid the fixture's pages from later tests; the fade above). The rest were real:

| Rule | Where | Fix |
|---|---|---|
| `color-contrast` (1.4.3) | the command palette's and trace picker's active row, dark: muted text `#8d96aa` on `#2c374f`, 4.06:1 | the active row's path and kind move a fifth of the way to `--text`: 4.98:1 dark, 6.55:1 light (`chrome.css`; `tokens.test.ts` checks the pair and the CSS) |
| `scrollable-region-focusable` (2.1.1) | the inspector's code preview, which scrolls sideways, couldn't be reached by keyboard | its `<pre>` is a Tab stop, a `group` named "Code from <path>", its focus ring inset (`Inspector.tsx`) |
| `aria-prohibited-attr` (needs review) | that `<pre>` and Add to README's Markdown `<pre>` carried `aria-label` with no role | both are `role="group"` |
| `label-content-name-mismatch` (2.5.3) | every canvas box: "db, datastore" also shows "PostgreSQL" | see below |

**Boxes.** A box's accessible name is its label and kind ("db, datastore"), then its states. The `aria-label` replaces the box's content, so a screen reader never heard its subtitle, counts, or a model's fields. Those are now the box's description (one hidden, comma-joined string the box's `aria-describedby` points to), and the visual copies are `aria-hidden`: a screen reader hears "db, datastore", then "PostgreSQL". In the browser: `db` has the description "PostgreSQL", and `@shop/web` "Next.js, apps/web, …" (checked by the diagram screen). axe's rule still flags the boxes, because it reads all visible text, `aria-hidden` or not, as the label, and wants it in the name in order ("db PostgreSQL, datastore"). WCAG 2.5.3 asks that the visible *label* be in the name, best at its start, and the subtitle is supplementary text. So the audit accepts this one rule only on a canvas box whose name starts with the words of its visible name and whose exposed text is that name alone; it fails anywhere else (ADR-0263 lists the alternatives).

**Mutation check.** With the palette color, the `<pre>`'s Tab stop, and the subtitle's `aria-hidden` each reverted (one build), 22 runs failed, each naming its rule: `color-contrast` only on the two dark palette screens, `scrollable-region-focusable` on the selection and trace screens, `label-content-name-mismatch` on every repo-page screen. Restored: 44 of 44 pass.

## Checked by hand: what axe couldn't decide

The final run passes 44 of 44. axe left one rule as "needs review": `color-contrast` for the text in the canvas boxes (names, subtitles, badges; 136 elements over the 22 repo-page runs). The canvas is a transformed layer under the SVG lines, so axe can't tell the background. The colors are tokens: `--text` and `--text-muted` on `canvas`, `surface-1` (a box), `surface-2`, and `surface-raised` are each at least 4.5:1 in both themes (`tokens.test.ts`, "meets WCAG 2.2 AA"); the lowest is muted text on `surface-raised` in dark, 5.36:1 (light: on `surface-2`, 5.56:1). Two box states are faded on purpose and fall below that: a box off the request path in a trace (20% opacity, 50% on hover) and a removed box in diff mode (its text at 50%). Both are context around the active content, the trace's path or the change list, and neither relies on the faded text: a traced box's name says "On the request path", and a removed box's badge stays at full strength and its name says "Removed in this change". That's a judgment, recorded here, not something axe checked.

## What axe doesn't check

Automated rules find only part of WCAG's failures. Keyboard paths through the diagram, focus recovery after overlays close, live announcements, and reduced motion are specified in UX.md and covered by the viewer's and explorer's tests (`Explorer.test.tsx`, `a11y.test.ts`, `diffMode.test.tsx`) and `explorer.e2e.ts`. No screen-reader session (NVDA, VoiceOver) was run: that needs a person.
