# env-example-prefix

Tests: an env-var URL base whose path is only in a committed example env file (ADR-0202). `@example-prefix/client` reads `import.meta.env.VITE_SERVER_BASE_URL` with no fallback in code, and `client/.env.example` sets it to `http://localhost:5000/api`, so `${BASE}/auth/login` and `${BASE}/blog/${blogId}` are `heuristic` edges to `POST /api/auth/login` and `GET /api/blog/:blogId` in `@example-prefix/server`, whose routers are mounted under `/api`. `VITE_ADMIN_API_URL` has the same example value and a code fallback that already holds `/api` (ADR-0158), so `${ADMIN}/stats` still reaches `GET /api/stats` (the prefix isn't added twice). `VITE_PAYMENTS_API_URL`'s example has no path, so `${PAYMENTS}/checkout` matches no route and is `unresolved`, though `POST /api/checkout` exists: nothing is guessed. No graph string holds the example's values.
