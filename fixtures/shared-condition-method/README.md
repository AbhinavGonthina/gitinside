# shared-condition-method

A URL and a method chosen by the same condition (M12.1e5, ADR-0311), as in agentboard-ce's and relay-status-monitor's forms. When the condition is an identifier bound to a `const` or to a parameter nothing assigns (destructured too), it can't change between the two reads, so both conditionals take the same branch, and each URL goes with its own method: `agentForm` (`const isEditing = !!agentId`, read in a nested submit handler), `saveKey` (a destructured `keyData` prop), `saveNote` (a `!` in the method's condition flips the pairing), `saveProject` (a `!` in the URL's condition, and the whole init chosen by the same parameter), and `saveDraft` (through the helper `save(base, id)`, whose own parameter chooses both) each link the collection's `POST` and the item's `PUT`, both `exact`, and never the unsent `PUT` to the collection or `POST` to an item.

Every path serves two methods, so a request whose method isn't read is `AMBIGUOUS`. The controls in `controls.ts` stay that way: a `let` (`draftLet`), a parameter that's assigned (`draftAssigned`), a property read (`draftProperty`), two different conditions (`draftOther`), a second condition in the URL (`draftNested`) or in the method (`draftNestedMethod`), and a call (`draftCall`).
