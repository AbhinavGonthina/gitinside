# next-rewrites

Tests: `next.config`'s `basePath` and `rewrites` (ADR-0206). `@next-rewrites/web`'s `next.config.mjs` (wrapped in `withBundleAnalyzer`) sets `basePath: "/shop"` and returns `beforeFiles`, `afterFiles`, and `fallback` rewrites. So `fetch("/shop/api/items")` is an `exact` edge to the app's own `GET /api/items`, while `fetch("/api/items")` matches nothing and is `unresolved` with a detail naming the `basePath`. `/shop/legacy/items` is rewritten (`beforeFiles`) to the app's `/shop/api/items`. `/shop/backend/users/${id}` is sent to `http://localhost:4000/users/…`, a `heuristic` edge to `@next-rewrites/api`'s `GET /users/:id`, not its `/backend/users/:id` decoy. `/shop/weather/${city}` is an `external_call` to `api.weather.example.com`, and `/status` (`basePath: false`) one to `status.example.com`. `/shop/api/items/${id}` is served by the dynamic route `app/api/items/[id]` before the `fallback` rewrite is tried, while `/shop/orders`, which nothing in the app serves, falls back to the Express server's `GET /orders`. The config is read as syntax, never loaded or run.
