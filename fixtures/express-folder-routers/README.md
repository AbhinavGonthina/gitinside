# express-folder-routers

Tests: routers loaded from a folder listing (M5A.3e, ADR-0162). `src/routes/createRouter.ts` builds one router from `glob.sync(\`**/*.${ext}\`, { cwd: \`${__dirname}/\` }).map((f) => require(\`./${f}\`)).filter(…).reduce((root, r) => root.use(r.default), Router())` (`ext` is `ts` or `js`, so both are listed; the filter isn't read), and `src/server.ts` mounts it at `/api`, so `routes/v1/users.ts` and `routes/v1/orders.ts` serve `GET /api/v1/users/:id` and `POST /api/v1/orders`. `routes/v1/helpers.ts` is listed too but exports no router. `src/legacy/index.js` mounts every file `fs.readdirSync(__dirname)` lists at `/legacy/<basename>` (itself excluded), so `legacy/reports.js` serves `GET /legacy/reports/daily`. `src/server.ts` also mounts each file `readdirSync(path.join(__dirname, "api"))` lists at `/api` through `const route = require(…)`, `const router = route.default || route` (maxun's loop, M9.1a5), so `api/robots.ts` (a default export) serves `GET /api/robots/:id` and `api/runs.js` (`module.exports`) serves `POST /api/runs`. `src/client.ts` calls all six routes root-relative from the same service: `GET /health`, mounted in code, is `exact`; the five reached through a listing are `heuristic`, because the listing's filters aren't evaluated.
