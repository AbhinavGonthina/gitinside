# spread-chain-method

A caller's method carried through two helpers by a spread (M12.1e3), as in DreamingEnglish's `'use server'` helpers. `serverApi(path, options)` adds a cookie with `api(path, { ...options, headers: { ...options?.headers, cookie } })`, and `api` sends `fetch(\`/api${path}\`, options)`. The method in the outer helper's spread is the caller's: `addToHistory` (`{ method: "POST" }`) links `POST /api/history`, and `listHistory` (no options, so the spread copies nothing) links `GET /api/history`. Order counts as for any spread: `forcePost` writes `method: "POST"` after the caller's options, so `replaceHistory`'s `DELETE` loses (`POST`), and `remove` writes `method: "DELETE"` before them, so `clearHistory` (no options) sends `DELETE` and `readHistory` (`{ method: "GET" }`) `GET`. Two controls stay `AMBIGUOUS` between the path's three routes: `syncHistory` passes options the analyzer can't see (its own parameter), and `withExtra` spreads a call's result after the caller's options, which could set any method.
