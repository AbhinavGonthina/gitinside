# conditional-method

A request method chosen by a condition (M12.1e2), as in RentTools.io's admin panel and comments widget. When every branch is a literal method, the site sends each of them, so it links one route per method (EVALUATION.md's two labels for such a site): `toggleSuspend` (`method: isSuspended ? "DELETE" : "POST"`) links `POST` and `DELETE /api/admin/users/:id/suspend`, `moderate` (the whole init a ternary of object literals) links `PATCH` and `DELETE /api/blog-comments/:id`, and `upvote` calls the wrapper `vote(path, up)`, whose own `fetch` chooses the method, linking `POST` and `DELETE /api/posts/:id/vote`. `archive` links `PUT /api/posts/:id/archive`, and its `DELETE` has no route, so it's shown unresolved (`NO_MATCHING_ROUTE`) beside the edge. The control `edit` chooses between a parameter and `"PATCH"`, so its method stays unknown and the request is `AMBIGUOUS` between the path's two routes. `saveDraft` picks its URL and its method from one parameter nothing assigns, so since M12.1e5 they pair branch by branch: `PUT /api/drafts/:id` and `POST /api/drafts`, both `exact` (no `POST /api/drafts/:id` or `PUT /api/drafts` is drawn; `shared-condition-method` has the controls). And `report`'s URL is only known at runtime (`DYNAMIC_URL`), so it stays one request whose method is shown as `?`.
