# Shared module resolutions: calcom/cal.diy (M5.13a4b, 2026-11-04)

- **Repo:** https://github.com/calcom/cal.diy at `2eb48eccd8aca8a0c0ffabf28cf92e298b33ecee` (5,075 source files, 113 services), the checkout M5.13a2 used.
- **Change measured:** a module-resolution cache shared by every service program with the same TypeScript resolution key (`getKeyForCompilerOptions` over `moduleResolutionOptionDeclarations`, `pathsBasePath` included), one entry per key, resolution mode, containing folder, and specifier. Each entry keeps the repo reads and probes its resolution made, and every service that uses it records them in its observed inputs. A miss resolves without TypeScript's own cache, so its probe list is complete. Code: commit `a397062` on branch `ci/m5.13a4b-shared-resolutions`, **not merged**.
- **Before:** `main` at `a397062` (ADR-0197's shared parses). The same built analyzer with only `program.js` swapped for HEAD's (scratch `packages/analyzer/dist/make-old.mjs`), so nothing else differed.
- **Method:** scratch `bench/dist/m513a4b-resolutions.mjs`: the analyzer's inventory, workspace, preloaded files, and `buildServicePrograms`, then every program built and timed; heap is `heapUsed` afterwards. On this laptop, runs alternated between the two builds, nothing else running. Not the 1-vCPU workflow: the result below is clear-cut, and a laptop pair is enough to reject a change (lessons: compare only within a pair).

## Resolutions

From each built program's import literals (scratch script above):

```json
{"services":113,"perProgram":24119,"shared":22555,"resolutionKeys":20}
```

- `perProgram`: distinct (folder, specifier, mode) each program resolves, summed over programs: what each program's own TypeScript cache already resolved once.
- `shared`: distinct (resolution key, folder, specifier, mode) over the run: the misses a shared cache runs. **6.5% fewer.**
- 113 services have 20 distinct resolution keys: most configs with `paths` give their own `pathsBasePath`, which (unlike in ADR-0197's parse key) really does change a resolution, so it can't be dropped.

## Time and heap (building all 113 programs)

| Build | Runs (s) | Heap after (MiB) |
|---|---|---|
| Before (`a397062`) | 18.3, 19.2 (18.6 under `--cpu-prof`) | 1,096, 1,083 (1,100) |

CPU profiles of one run each: module resolution (`resolveModuleName` and below) took about 4.6 s before and 7.3 s after. `forEachAncestorDirectory` alone was 6.8 s after, and package.json parsing (`convertObjectLiteralExpressionToJson`) 0.6 s: without TypeScript's cache, each miss redoes the package.json lookups and the folder walk that the program's cache shared within a program.

## Observations (hand-written, not generated)

- **Not landed: slower and bigger.** Building every program took 4–6 s longer (about +25%) and the heap grew by about 40–50 MiB (the kept probe lists), in every pair.
- **Why so little sharing.** ADR-0197 shared 27% of parses because a parse doesn't depend on `paths`. A resolution does, and cal.diy's services mostly have their own `paths` base, so only 6.5% of resolutions repeat across programs with the same key.
- **Why each miss costs more.** For `verifyInputs` to see every read, a shared resolution needs its complete probe list, and TypeScript's cache skips probes on its hits (folder results, package.json info). So misses ran without it and redid that work: about 0.27 ms per miss against 0.19 ms per resolution before.
- **What could still work, and why it isn't worth doing now.** Relative specifiers don't read `paths` or `baseUrl`, so a key without them for relative names would share more. But each miss stays slower than a cached resolution, so even halving the misses would save about 1 s locally, and the probe lists cost heap, which ADR-0197 had just lowered. M5.13a5 (the collector) is next.
