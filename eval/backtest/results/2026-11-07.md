## Limitations

- **Not a blind test.** The first full replay (ADR-0216's M7.2c3 amendment) flagged no break at all. A hand check of a sample of that replay ([`eval/results/2026-11-backtest-zero-check.md`](../../results/2026-11-backtest-zero-check.md), M7.2d) found getmaxun/maxun#1157 merged a real break the detector couldn't see, and the detector gained the rule that now flags it (calls to a removed function whose name the caller still imports, ADR-0087's M7.2e amendment) before the replay was run again (M7.2f). So the flagged breaks come from a rule written after seeing this data. The re-run flagged nothing new in any other PR, but these numbers aren't evidence of what the detector finds on unseen PRs.
- **Recall isn't measured.** Only 38 of the 926 PRs were checked by hand for breaks the detector missed (M7.2d), plus a census of all 926 for merges that empty a source file (only #1157 does). Outside that sample a missed break would not show here. Known blind spots, each documented in `detectBroken` (`packages/diff/src/broken.ts`): a function that stays but stops being exported; a change in what a kept connection expects (arguments, body, response shape), which only the contract checks look at (ADR-0088); and any connection the analyzer can't resolve to an edge in the first place (tRPC and GraphQL calls, requests through wrappers it can't follow, backends it doesn't support), since only an edge can break.
- **The verdicts are drafts.** Claude drafted every verdict, and the same model family wrote the detector. The report counts reviewed and draft verdicts apart; until Abhinav reviews them, "true break" means "drafted as a true break". A verdict is a judgment, with permalink evidence so it can be checked.
- **Small numbers.** All flagged breaks come from one PR with one cause (a file emptied by mistake), so the precision above is a count for these breaks, not an estimate for the detector in general.
- **Not cross-service.** The flagged breaks are function calls inside one service (`calls` edges). No request→route (`http`) edge was flagged in any PR, so this backtest gives no measured example of the broken cross-service connections the PR bot is mainly for.
- **The repos.** 7 repos, fewer than the ~8 planned: most well-known apps in the supported stack failed the rule of at least 20 resolved requests to routes from app code (ADR-0214). The candidate list started by hand, so the set isn't a random sample of apps in the stack, and every count here describes these 7 repos and this window only.
- **What a fix is.** A break counts as fixed at the first later commit where the same detector no longer flags it (ADR-0217). That can be coincidental (a caller rewritten for another reason), which is why each fix is judged. Commit times are the committer's clock, so "after" trusts it.
- **Pins.** getmaxun/maxun's `startSha` is a commit on a PR branch that `develop` merged later, not a state of `develop` (ADR-0215); only the measurements that picked the repo used it, never the PR list or the replay.
- **Machines.** The raw files were made on GitHub's Linux runners with different CPU models (see Inputs). The results don't depend on the machine; only run times would, and this report quotes none.
